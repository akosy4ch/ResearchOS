# ResearchOS

ResearchOS is a local-first research copilot for turning a question or early idea into a source-linked literature review and a practical research plan.

The current build includes a responsive local web app, project workspaces, a dedicated **Find papers** search, a saved paper library, a separate **PDF analysis** service, live research run progress, an agent journal, and source-linked reports. Find papers searches Crossref, Europe PMC, and OpenAlex for up to 100 records per index; results remain temporary until the user saves them. Saved papers keep abstracts, citation metadata, and trusted source links. A run can save a structured brief covering goals, field, data, methods, contribution, resources, timeline, and success criteria. The interviewer and lead use it to plan search branches and surface scope-changing questions. Research runs search the same three indexes across distinct branches, screen out index records with insufficient topic overlap, attach project PDFs only when their title/text match the question, read up to three user-provided pages only from the trusted scholarly-domain allowlist, deduplicate records, extract source-quoted claims, methods, metrics, and per-paper annotated-bibliography appraisals, and produce a detailed synthesis, provisional novelty review, feasibility assessment, experiment plan, and adversarial review. The report's **Literature review** section shows search coverage and, for each analyzed paper, what it did, relevance to the question, evidence-backed strengths, and stated limitations. Unsupported facets are explicitly marked not assessable.

The Systems Engineer checks source syntax, app startup, the SQLite database, and the local model. It records server and research-run failures, reviews incidents in the background, and proposes small improvements in a weekly review. When a concrete source defect is found, it may apply exact replacements in an allowlisted set of app files after staged and live startup checks; it keeps backups and rolls back a failed validation. A healthy weekly review may apply one small behavior-preserving improvement through the same checks. Manual reviews leave suggestions for you. The app does not let the model run shell commands, change dependencies, or access research files, credentials, or the database.

## Local-first setup

- Target: Apple silicon MacBook Pro, macOS, 16 GB unified memory.
- Inference: local model server through an OpenAI-compatible API. The Model Manager can connect to local Ollama or a local llama.cpp server, download Ollama library models, search public Hugging Face GGUF repositories, and save selected GGUF files under `data/models/huggingface`. A downloaded GGUF can be served by llama.cpp and selected in the app through its local server address. Research runs, PDF analysis, and report/paper chat can each use an installed chat model; all local model calls pass through a single queue, and the app reports per-task call and token totals for the current server session.
- Paper retrieval: optional SPECTER2 query and proximity adapters provide local scientific-semantic ranking for Find papers and research runs. The Model Manager can install the PyTorch runtime and fetch the roughly 450 MB base weights and adapters on demand; those files are stored under `data/models/huggingface`. SPECTER2 ranks metadata from trusted indexes and never writes report text. Keyword/topic screening and source/provider balancing remain in the workflow.
- Storage: SQLite and local files for the first version. No hosted database or paid API is required.
- Research sources in this build: Crossref, Europe PMC, and OpenAlex scholarly metadata APIs. OpenAlex is queried without an API key for casual free use. Optional page reading accepts HTTPS URLs only from an explicit allowlist of scholarly indexes, preprint servers, and publishers; it does not accept arbitrary websites or bypass logins and paywalls. This is a domain trust boundary, not a guarantee that every page or claim is peer reviewed.
- Agents: separate research roles are workflow steps and independent review passes. They do not each need a separate model or simultaneous model load.

## Start in one click (macOS)

Install Python 3.11+ and Ollama, then double-click `Start ResearchOS.command`. The launcher creates the local Python environment, installs project dependencies, starts Ollama when available, runs the startup check, and opens the app. Keep its Terminal window open; press Control-C there to stop the server. See the [macOS quick-start guide](docs/quickstart-macos.md) for model setup and troubleshooting. The `researchos serve` command supervises the app and restarts it after a validated runtime repair.

Windows and Linux users can follow the [Windows/Linux quick-start guide](docs/quickstart-windows-linux.md), which includes matching first-run launchers and offline-check steps.

For manual setup, environment variables, API use, and the offline checks, follow the [macOS quick-start guide](docs/quickstart-macos.md).

The app searches only the configured scholarly metadata APIs: Crossref, Europe PMC, and OpenAlex. It does not perform general web search, fetch paywalled full text, or control an existing browser session. Each branch requests up to 20 results per provider; after deduplication, at most 48 source links are retained in a run. Newly retrieved abstracts are kept only for the 12 records reserved as local model inputs; the wider candidate pool stays in memory for that run and is discarded. Model analysis is optional: source search and paper storage can run while the local model server is offline.

Add optional source URLs in the overview composer or new-research form. Only HTTPS links whose host matches the trusted scholarly-domain allowlist in `src/researchos/web_reader.py` are accepted; redirects outside that list are blocked too. Pages are limited to 2 MB and 18,000 extracted characters, and saved as text with the final URL. The reader blocks private/local IP addresses and nonstandard ports. It reads static page text and does not execute site JavaScript. Local PDFs remain user-provided sources and are not checked against this web-domain allowlist.

Use **Add PDFs** in Paper Library to attach up to three papers at a time to the selected project. Text is extracted locally page by page, stored with page numbers, and included in later runs for that project. Each file is limited to 15 MB, 250 pages, and 60,000 extracted characters. A run reads the three most recently added project PDFs. Scanned-image PDFs need OCR, which is not included yet.

Open a completed report to chat with the local model about its findings. The conversation is saved with that report, uses its source excerpts and verified claims, and links citations back to the cited sources. Use **Find papers** to search more than the papers retained by one research run; results are not saved unless selected. If a paper already exists in the library, the search result links to its reports, metrics, and PDF analysis. In **Paper library**, search saved titles, authors, or DOIs to see prior report findings and reported metrics. **PDF analysis** is its own workspace: select a local PDF in the left panel, then view its detailed report and ask paper-specific questions in the main panel. The dossier covers research question, contribution, study design, dataset, preprocessing, model architecture, baselines, experimental protocol, metrics, results, statistics, ablations, limitations, reproducibility, and future work. Every factual summary and paper-specific Q&A answer points to validated finding IDs, exact quoted text, and PDF pages. Copy a suggested citation or BibTeX record from the saved bibliographic metadata; verify it against the publisher. The service also saves compact previews of up to eight pages whose captions or text suggest architecture, data, experiment, or result figures. Each preview links to the original PDF page; previews stay local, are capped at 10 MB per analysis, and are not sent to the text model. Scanned pages without extractable text may be missed. The analysis distinguishes the paper's own state-of-the-art claim from current SOTA, which one paper cannot establish.

## Cost and memory

The software stack can be used without subscription fees. Public search APIs may have rate limits, and access to some full texts depends on open-access status or files you provide. ResearchOS sends prompts only to the connected local inference endpoint. Model settings can download Ollama library models, public GGUF files, and optional SPECTER2 packages/weights. Search and downloads contact those services and reveal ordinary network metadata; private browsing does not hide an IP address. Downloads use disk space and bandwidth and only start when chosen. Model-heavy work inside ResearchOS runs one task at a time to fit a 16 GB Mac; the picker shows file size and a rough memory estimate where available.
