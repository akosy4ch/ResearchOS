# Literature review in ResearchOS

ResearchOS treats a literature review as both a synthesis and an auditable record of how the evidence was found. Open a completed research run and use the **Literature review** section before reading its themes and recommendations.

## What the report shows

- **Search scope and reproducibility:** the report records each trusted provider, query branch, timestamp, per-provider hit count, provider errors, exact topic terms, ranking method, duplicate count, configured retention cap, model, and analysis subset. Topic screening is a lightweight lexical pass and can miss relevant work described with different terminology; inspect the queries and use **Find papers** with alternate terms when needed.
- **Screening inbox:** retained records can be marked include, exclude, or maybe with a reason. Decisions are reversible, saved per run, appear in the agent journal, and are included in report exports. They document a screening pass without silently rewriting the already-generated synthesis. Candidate abstracts outside the retained set are discarded after the run; their contribution remains visible in the “outside run cap” count.
- **PRISMA-style flow:** identification hits, duplicates, unique records screened, topic exclusions, records eligible after the automatic screen, records beyond the retention cap, and researcher decisions are shown separately. These are operational counts for the run, not a claim that ResearchOS completed a systematic review.
- **Annotated bibliography:** for each analyzed paper, the report asks what the study did, how it relates to the current question, what strengths are actually supported by the supplied text, and what limitations the authors state. Each populated assessment includes a source excerpt and a link to the paper or local PDF.
- **Not assessable:** if the abstract or excerpt does not support an assessment, the report says so. In particular, a limitation missing from an abstract is not treated as a flaw in the paper, and an unmentioned limitation is not treated as proof that none exists.
- **Cross-paper synthesis:** themes, disagreements, and possible research gaps remain separate from the paper-by-paper annotations. Gaps are provisional; a bounded search cannot establish that no prior work exists.
- **Evidence matrix:** every analyzed paper gets the same 13 facets: study design, cohort/dataset, sample size, preprocessing, architecture, baselines, data splits, experiment protocol, metrics, statistics/uncertainty, ablations, limitations, and reproducibility. Populated cells link an exact quote to its abstract, full-text section/table/figure caption, or PDF page. Empty cells say “not found in available text,” not that a study omitted the detail. If no extractor ran, cells say “not assessed.”
- **More full text:** for up to three analyzed Europe PMC papers per run, ResearchOS can request text through the documented REST fullTextXML service when the record has a PMCID, is in the open-access subset, and its XML has an explicit CC0 or adaptation-permitting CC license. It sends bounded passages to the local model, reads table text and figure captions, and does not keep the full XML. A caption is not figure interpretation; image contents are not analyzed by the research workflow.
- **Comparable metrics:** source-reported results are grouped only when the normalized metric, dataset, split, and evaluation-protocol excerpts match. Values and units remain verbatim. Other numbers stay in their paper’s own record instead of appearing in an SOTA leaderboard.

## How these choices map to good-review practice

The supplied guidance recommends searching broadly, keeping references organized, appraising each source consistently, grouping sources into themes, citing literature-supported statements, and revisiting the review near the end of a project. ResearchOS supports a bounded, traceable search and lets the researcher screen retained records, but it is not yet a complete systematic-review manager: it does not retain all unselected records, trace citations forward/backward, or export full RIS/BibTeX/PRISMA packages. Use **Find papers** for broader focused searches, save records selected for the review, attach full-text PDFs when available, and rerun the search before final submission. Older reports offer **Run this review again**, which reuses the question and brief.

The pasted guidance's suggested impact-factor cutoff is not used as a universal quality test. Journal impact factor is not a substitute for relevance, study design, reporting quality, or source type, and its meaning varies across fields. ResearchOS therefore surfaces source type and evidence detail but leaves final inclusion and quality judgments to the researcher.

## Reading the counts

The broad provider result pool is temporary. A run retains a bounded set of source links and keeps full abstracts only for records selected for local analysis; licensed Europe PMC passages are used in memory, while only validated excerpts and links enter the report. Thus **records analyzed** is smaller than **unique records** by design. The visible counts, search queries, source errors, and coverage notes should guide follow-up searches; they must not be reported as proof that the field contains only those papers.
